## 0. Правила для каждого агента

Перед началом **любой** задачи прочитать: `docs/architecture.md` (целиком), разделы GDD, указанные
в карточке, и `docs/Technical Task.md`.

**Definition of Done — одинаков для всех задач:**

1. Проект компилируется; **ни одного варнинга** в затронутых сборках.
2. Edit-mode тесты из карточки зелёные; ранее написанные тесты не сломаны.
3. Соблюдены инварианты I1–I10 (`docs/architecture.md` §1). Особенно: нет потоков, нет
   `.Result`/`.Wait()`, нет `UnityEngine.Random`, нет legacy `Input.*`, R3-подписки и твины
   освобождаются.
4. Публичные типы и имена — ровно те, что заданы в `docs/architecture.md` (§5, §6, §7). Нужно
   другое имя или другая схема — правим документ **в том же PR** и пишем почему.
5. Прогнан self-review: `/match3-code-review` по своему диффу; блокеры и Major устранены.
6. Ветка `feature/<snake_case_slug>`, в описании PR: что сделано, какие `D`/`E`/`§` реализованы,
   какие тесты, чем проверять (сцена, уровень, seed, чит), для визуального — gif/видео.
7. **Unity Editor закрыт перед коммитом** (требование стандартов ICVR: иначе теряются кэшированные
   изменения).

**Запрещено без согласования:** менять схему транскрипта (§6 архитектуры), добавлять UPM/NuGet
пакеты, менять `ProjectSettings`, переименовывать публичные типы из чужих задач, класть что-либо
в `Assets/Resources`.

**Шаблон запуска агента:**

```
Прочитай docs/architecture.md, docs/gdd-match3.md (разделы из карточки) и docs/tasks.md.
Выполни задачу <ID> из docs/tasks.md целиком, включая тесты и Definition of Done (§0).
Не выходи за «Не входит в задачу». Если требуется отклонение от архитектуры — сначала
обнови docs/architecture.md с обоснованием в том же изменении.
```

### T04 — Формат уровня: парсер, валидатор, генерация начального поля

| | |
|---|---|
| Сборка | `Match3.Levels` |
| Зависимости | T03, T05 (`LegalMoveService`), T06 (`GoalDefinition`) |
| GDD | §10.1, §10.2, §3.4, §9.3, `D01`, `E20` |
| Архитектура | §9, `A05`, `A06` |

**Объём:**

- `LevelData` (DTO), `NestedContent`, `ColorWeight`, `TokenGrid`.
- `LayoutParser`: токен = 2 символа, разделитель — пробел; **первая строка = `y = height − 1`**
  (`D01`), флип **ровно один раз**; внятные ошибки на неизвестный токен, длину токена, число строк
  и ширину строки.
- `LevelValidator` (§3.4): достижимость по графу потока (непроходимы только `__` и `##`),
  нет готовых матчей, есть легальный ход, цели достижимы (препятствий нужного типа ≥ target),
  вложенность ≤ 3, `colorCount ∈ [4,6]`. `ValidationReport` со списком проблем.
- `FlowReachabilityAnalyzer` — граф по правилам §5.3 (вертикаль + диагонали), плюс проверка
  «сплошной блок стен не шире 2» как предупреждение (§10.3).
- `BoardBuilder`: `LevelData + IRandom → Board`; `E20` — заполнение `y↑, x↑`, перевыбор цвета при
  замыкании линии из 3 (до `colorCount − 1` попыток, затем любой не образующий линию), затем
  проверка легального хода, до 50 регенераций, затем ремонтный проход свапами. Начальный цвет и
  фаза `cx` — из RNG в фиксированном порядке (§13).
- `MoveLimitCalculator` (§9.3): `work`, `thr`, `multiplier`, `moves = ceil(work / thr × multiplier)` —
  инструмент валидации, не рантайм.
- `BuiltInElementCatalog` — каталог §7.2 в коде для тестов.
- Хелпер для тестов: `TestLevel.From(@"...")` — `LevelData` из строковой раскладки.

**Готово, когда:**

- [ ] Тест флипа: `layout` из 3 строк → клетка первой строки оказывается на `y = 2`; двойного
      флипа нет.
- [ ] Тесты ошибок формата: неизвестный токен, токен из 1/3 символов, лишняя строка, короткая
      строка — все падают с внятным сообщением.
- [ ] Тест `E20`: сгенерированное поле не содержит готовых матчей и содержит легальный ход
      (100 разных seed).
- [ ] Тест ремонтного прохода: на заведомо тесной раскладке ремонт срабатывает и не зацикливается.
- [ ] Тест валидатора: мёртвый карман под блоком стен шириной 3 отклоняется; уровень 5 из §10.3
      проходит.
- [ ] Тест `MoveLimitCalculator`: уровень 5 → 26; уровень 11 → формула даёт 17 при конфиге 18
      (зафиксированное отклонение, предупреждение, не ошибка).
- [ ] `contents` парсится из отдельного списка, а не из сетки.

**Не входит:** ScriptableObject-и (T14), сами 12 конфигов (T14).

## 3. Что осознанно вне плана

Соответствует §16 GDD: монетизация, мета-слой, предматчевые бустеры, собираемые падающие элементы,
распространяющиеся препятствия и `UnderChip`/`OverChip` (оси объявлены, механики не спроектированы),
редактор уровней, горячие клавиши читов, музыка и озвучка, локализация, серверная аналитика.
Фоновая амбиентность, кнопка выключения звука и слой звуковых эффектов (T34, §11.4 GDD) добавлены
вне плана, по отдельному запросу.

Если задача упирается в один из этих пунктов — это сигнал, что она вышла за скоуп: остановиться и
спросить, а не расширять реализацию.
