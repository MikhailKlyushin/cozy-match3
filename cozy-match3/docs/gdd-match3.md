## 1. Обзор

Казуальный match-3 на Unity WebGL: поле 7×7–9×9, 4–6 цветов фишек, лимит ходов, набор целей
уровня. Референс по набору бустеров и фильингу — Homescapes / Royal Match, по опаданию и
каскадам — Gardenscapes. Сессия: один уровень 1.5–3 минуты, 12 уровней последовательно; при
победе — следующий уровень, при поражении — переигрывание текущего.

Отличительной механики у сборки нет и не планируется: это тестовая реализация ядра жанра.
Ценность документа — не в новизне, а в том, что жанровые правила зафиксированы однозначно:
одновременность событий в цикле хода, полная матрица комбинаций бустеров, оси расширения
препятствий и вывод лимита ходов.

## 2. Ключевые решения

Решения, принятые этим документом. Спорные вынесены в §15 с указанным дефолтом.

| # | Решение | Почему |
|---|---|---|
| D01 | Начало координат — левый-нижний угол, `(0,0)`; `x` вправо, `y` вверх; гравитация по `−y`. В конфиге сетка пишется «картинкой», сверху вниз | Половина багов поля — расхождение в origin между дизайном, конфигом и кодом |
| D02 | Матч определяется **примитивами** (линия ≥3, квадрат 2×2); примитивы, делящие клетку, объединяются в **компонент**. Один компонент → максимум один бустер, чистятся **все** клетки компонента | Альтернатива (жадное присвоение фишек фигурам) оставляет на поле «недоматченные» фишки — игрок читает это как баг. См. §4.2 |
| D03 | Бустеры активируются **тапом** (1 ход), а также свапом с фишкой и свапом с другим бустером | Стандарт Royal Match; без тапа бустер в углу без пары недоступен |
| D04 | Ход списывается на стадии COMMIT — сразу после валидного ввода, до разрешения поля | Счётчик реагирует мгновенно; иначе игрок успевает сделать второй ввод «бесплатно» |
| D05 | Ввод во время разрешения поля **игнорируется**, а не буферизуется | Буферизация даёт рассинхрон визуала и модели; жанровый стандарт |
| D06 | Бустеры, созданные в каскаде, **появляются, но сами не срабатывают** | Иначе игрок теряет контроль над своим же бустером |
| D07 | Урон препятствию — **1 экземпляр на источник за шаг разрешения**. Два разных источника в одном шаге = 2 урона | Однозначно решает E09/E11: без этого 2-hp ящик ведёт себя по-разному у двух программистов |
| D08 | Бустер срабатывает не более одного раза за шаг разрешения (флаг `consumed`) + жёсткий кап 20 волн | Гарантия завершения цепочки |
| D09 | «Приоритет цели» и «самый нужный цвет» — **одно** детерминированное правило (§6.1) на самолётик и на все комбинации с радужным шаром | Два похожих правила разъезжаются при первой же правке |
| D10 | Опадание: вертикальное падение + **диагональное скольжение** «с полки», проходами до стабилизации | Без диагонали любое поле со стенами получает клетки, которые никогда не пополняются — проверено на раскладке уровня 8 |
| D11 | Ракета проходит **всю** линию и не останавливается на препятствии | «Останавливается» требует правил под каждый тип препятствия; «проходит» — одно правило на всех |
| D12 | Один RNG-поток на попытку уровня; seed логируется и вводится вручную из читов | Без этого баг-репорт «уровень непроходим» невоспроизводим |
| D13 | Лимит ходов **выводится** из объёма работы по целям (§9.3). Цветовые цели считаются параллельно (`max`), остальные — последовательно (сумма) | Наивная сумма по цветовым целям завышает лимит вдвое: один клир обслуживает все цветовые цели сразу |
| D14 | Победа приоритетнее поражения: если ходы кончились, а цели закрылись в том же разрешении — победа | E13/E14 |
| D15 | Подсказка после 5 с простоя показывает ход, **создающий бустер**, и никогда не предлагает тратить комбинацию «бустер + бустер». Выбор детерминированный, без RNG | Подсказка обязана разблокировать игрока и обучить формам, а не играть за него; детерминизм — чтобы её можно было покрыть тестом (§5.5) |

## 3. Игровое поле

### 3.1 Геометрия и координаты

- Размер `width` × `height` задаётся в конфиге. Рабочий диапазон 7×7 … 9×9.
- Начало координат — левый-нижний угол `(0,0)` (D01). Клетка `(x, y)`: `x ∈ [0, width)`,
  `y ∈ [0, height)`. Гравитация направлена в `−y`.
- В конфиге сетка записывается сверху вниз: первая строка блока `layout` — это `y = height − 1`.

### 3.2 Типы клеток

| Тип | Токен | Занимает клетку | Пропускает падение | Может быть целью |
|---|---|---|---|---|
| Играемая клетка | `..` / `t1`–`t6` | нет (в ней лежит фишка) | да | — |
| Нет клетки (дырка) | `__` | — | нет | нет |
| Неразрушимый блокер | `##` | да | **да, насквозь** (§5.3) | нет |
| Препятствие (ящики, §7.2) | `bx`, `b2`, `b3`, `c1`–`c6`, `cx` | да | нет | да |

«Занимает клетку» означает, что фишки в этой клетке нет и быть не может, пока препятствие живо.

### 3.3 Спавнеры

- По умолчанию спавнер — каждый столбец, у которого существует клетка в верхней строке
  (`y = height − 1`) и она не `##`. Поле `spawners` в конфиге переопределяет дефолт.
- Столбцы без спавнера пополняются провалом сквозь `##` из своей же верхней части, а если брать
  там нечего — диагональным скольжением (§5.3). Это законная конструкция уровня (уровни 10 и 12),
  но она обязана пройти валидацию достижимости.

### 3.4 Валидация уровня

Выполняется при загрузке конфига; в редакторе — с падением в ошибку, в билде — с логом.

1. Каждая играемая клетка достижима по графу потока хотя бы от одного спавнера (иначе «мёртвый
   карман», который никогда не пополнится). Граф строится по правилам §5.3: вертикаль, провал
   сквозь `##`, диагональ. Столбец обрывает только `__` — `##` фишку не держит, но пропускает
   сквозь себя, поэтому стена из `##` любой ширины мёртвого кармана не создаёт. Разрушаемые
   препятствия проходимы: они перекрывают поток временно, до своего уничтожения.
2. Начальная раскладка не содержит готовых матчей и содержит хотя бы один легальный ход (§13).
3. Цели физически достижимы: препятствий нужного типа на поле не меньше таргета цели.
4. Глубина вложенности препятствий ≤ 3.

## 4. Фишки и матчи

### 4.1 Фишки

- Цвета нумеруются `1…colorCount`, `colorCount ∈ [4, 6]`. Цвет — это индекс; визуал (спрайт,
  форма) привязан к индексу.
- Веса спавна по умолчанию равномерные. Опциональное поле `spawnWeights` (цвет → вес) — это
  per-level данные, никогда не глобальная константа.

### 4.2 Определение матча

**Шаг A — примитивы.** На поле ищутся:

- **линия** — максимальный ряд из ≥3 фишек одного цвета по горизонтали или вертикали;
- **квадрат** — блок 2×2 из фишек одного цвета.

**Шаг B — компоненты.** Два примитива принадлежат одному компоненту, если делят хотя бы одну
клетку (транзитивно). Компонент — связная группа примитивов одного цвета.

**Шаг C — классификация.** Компонент даёт максимум один бустер, по высшему присутствующему рангу:

| Ранг | Что присутствует в компоненте | Бустер |
|---|---|---|
| 1 | линия длиной ≥5 | радужный шар |
| 2 | две **пересекающиеся** линии (каждая ≥3), суммарно ≥5 клеток — формы L, T, + | бомба |
| 3 | квадрат 2×2 | самолётик |
| 4 | линия длиной ровно 4 | ракета |
| 5 | только линии длиной 3 | нет бустера |

**Шаг D — очистка.** Чистятся **все** клетки компонента, независимо от ранга. Вопрос «какая
фигура забирает фишку, входящую в две фигуры сразу» (E02) в этой модели не возникает: фишка
принадлежит компоненту, а не фигуре, и компонент чистится целиком.

Следствия, которые нужно знать при реализации:

- Блок 2×3 одного цвета — один компонент (две линии по 3 + два квадрата 2×2) → ранг 3 →
  самолётик, чистятся все 6 фишек.
- Линия 4 + пересекающая её линия 3 (T-образная, 6 фишек) → ранг 2 → бомба, а не ракета.
- Линия длиной 6 → ранг 1 → радужный шар, чистятся все 6 фишек.
- Один ход может создать **два** бустера, если возникло два и более несвязанных компонента
  ранга ≤ 4 (E01). Каждый спавнится в клетке своего компонента.

### 4.3 Клетка появления бустера

Правило применяется к компоненту; берётся первое подходящее:

1. Клетка, **в которую** игрок сделал свап, если она принадлежит компоненту.
2. Ранг 2 → клетка пересечения линий. Если пересечений несколько — с минимальным `y`, затем
   минимальным `x`.
3. Ранг 3 → левая-нижняя клетка квадрата.
4. Иначе — медианная клетка: клетки компонента сортируются по `(y ↑, x ↑)`, берётся индекс
   `floor((n − 1) / 2)`.

Для компонентов, возникших в каскаде (без хода игрока), пункт 1 пропускается (E03). Если два
компонента претендуют на одну клетку появления, второй по порядку обхода использует правило 4.

**Ориентация ракеты** берётся из линии, давшей ранг 4: горизонтальная линия → горизонтальная
ракета (чистит строку), вертикальная → вертикальная (чистит столбец). Направление свайпа
ориентацию **не** определяет.

## 5. Цикл хода

### 5.1 Пайплайн

Позвоночник документа: все остальные разделы ссылаются на стадии этого списка.

```
IDLE
 ├─ таймер простоя: 5 с без ввода → показ подсказки хода (§5.5)
 └─ ввод игрока (свап двух соседних клеток | тап по бустеру)
     ├─ VALIDATE
     │    свап легален, если обе клетки играемые, содержат подвижные фишки/бустеры И
     │      (свап создаёт матч ИЛИ хотя бы одна из клеток содержит бустер)
     │    нелегален → отскок 0.10 + 0.10 с, ход НЕ списывается, → IDLE            (E16)
     ├─ COMMIT
     │    анимация свапа 0.15 с; здесь списывается 1 ход                     (D04, E15)
     └─ RESOLVE — цикл, повторяется до стабилизации поля:
          1. DETECT     примитивы и компоненты (§4.2)
          2. CLASSIFY   ранг компонента, клетка появления бустера (§4.3)
          3. SPAWN      помечаются создаваемые бустеры (не срабатывают)           (D06)
          4. ACTIVATE   волнами: сработавшие бустеры раскрывают свои клетки (§6.4)
          5. DAMAGE     урон препятствиям во всех задетых клетках, 1 на источник  (D07)
          6. CLEAR      удаление уничтоженного, зачёт целей, раскрытие вложенного
          7. ANIMATE    FX уничтожения доигрывают ДО начала опадания
          8. GRAVITY    падение и диагональное скольжение, проходами до стабилизации
          9. REFILL     спавнеры выпускают новые фишки
         10. STABLE?    появились новые матчи → шаг 1, depth += 1 (каскад)
                        нет → выход      (кап глубины каскада 30, при достижении — лог ошибки)
     └─ POST-TURN
          1. препятствия, меняющие состояние по ходам (цветной сменяющийся ящик), обновляются
          2. цели закрыты?        → WIN, бонус остатка ходов (§8.4)               (D14)
          3. ходов 0?             → LOSE
          4. легальных ходов нет? → перемешивание (§5.4)
     └─ IDLE
```

### 5.2 Одновременность — зафиксированные ответы

| Ситуация | Правило |
|---|---|
| Бустер создан в каскаде | Спавнится, не срабатывает (D06) |
| Два источника урона по одному препятствию в шаге | 2 урона, по одному на источник (D07) |
| Площадной урон накрыл препятствие несколькими клетками | 1 урон: источник один |
| Последняя цель закрылась посреди каскада | Каскад доигрывает полностью, затем экран победы (E13) |
| Ходы кончились, каскад ещё идёт | Каскад доигрывает, затем проверка целей; победа приоритетнее (E14, D14) |
| Ввод во время RESOLVE | Игнорируется, поле не принимает ввод (E17, D05) |
| Собрано больше таргета цели | Излишек отбрасывается, счётчик показывает `12/12`, никогда `14/12` (E18) |

### 5.3 Гравитация (стадия GRAVITY)

Разрешается проходами. Один проход обходит пустые клетки в порядке `y ↑, x ↑` и для каждой
пустой клетки `E`:

1. Если клетка **прямо над** `E` содержит подвижную фишку или бустер — она падает в `E`.
2. Иначе, если над `E` идёт цепочка клеток, занятых элементом, который **пропускает падение**
   (ось gravity = `StaticPassable`, §7.1; в скоупе это только `##`) — берётся первая подвижная
   фишка над этой цепочкой и **проваливается сквозь неё** в `E`, оставаясь в своём столбце.
   Цепочку обрывают дырка `__`, блокирующее препятствие и пустая клетка: пустую сначала заполнит
   обычное падение, и провал произойдёт следующим проходом.
3. Иначе, если клетка прямо над `E` не может принять фишку вообще (`__`, живое препятствие или
   `##`, над которым брать нечего) — проверяются две клетки по диагонали вверх: сначала
   верх-левая, затем верх-правая. Если в ней лежит подвижная фишка, которая **сама не может
   опуститься в своём столбце** (ни падением, ни провалом сквозь `##`), эта фишка соскальзывает
   в `E`.
4. Иначе, если `E` — верхняя клетка столбца-спавнера, стадия REFILL создаёт новую фишку.

Проходы повторяются, пока за проход происходит хотя бы одно перемещение. Порядок правил
(вертикаль раньше диагонали) и порядок диагоналей (левая раньше правой) — часть контракта: они
делают результат воспроизводимым.

Приоритет правила 2 над правилом 3 — это ответ на «карман над блокером»: клетку под `##` кормит
его собственный столбец, а не сосед. Диагональ остаётся для случая, когда над `##` брать нечего
(уровень 10: там над блокером стоят дырки `__`).

Падение блокируют `__` и любое живое препятствие (E10); `##` занимает клетку, но падение
пропускает. Мёртвое препятствие удалено ещё на CLEAR, поэтому падение через его клетку разрешено
в том же шаге.

### 5.4 Перемешивание

Триггер: на POST-TURN нет ни одного легального хода.

1. Цвета фишек собираются в список и перемешиваются (Fisher–Yates из RNG-потока попытки).
   Препятствия и блокеры **не двигаются**, новые фишки не спавнятся — игрок замечает изменение
   цветового распределения.
2. Результат проверяется: нет готовых матчей И есть хотя бы один легальный ход.
3. До 10 попыток. Затем цвета генерируются заново по `spawnWeights` (ещё до 10 попыток).
4. Если и это не помогло — третья фаза, детерминированная: каждая клетка получает цвет, не
   замыкающий примитив (то же правило, что у генерации начального поля, `E20`), поэтому готовых
   матчей нет по построению; если легального хода всё равно нет, пары фишек меняются местами,
   пока он не появится. Каждая пара пробуется не более одного раза, проход конечен.
5. Если и третья фаза не справилась (например, на поле осталось меньше 3 подвижных фишек) —
   уровень завершается: победой, если цели закрыты, иначе поражением с причиной `deadlock`.
   Событие логируется как баг, а не как баланс (E19).

Третья фаза добавлена по результатам прогона ботом (T26): первые две перебирают расстановки
случайно, и на раздробленном поле 20 попыток недостаточно, чтобы наткнуться на расстановку без
готового матча. Это давало `deadlock` примерно на каждом восьмом перемешивании — то есть §5.4 в
исходной редакции не мог выполнить собственное требование `E19`.

Анимация: 0.35 с разлёт + 0.35 с сбор, ввод заблокирован.

### 5.5 Подсказка хода (idle hint)

**Триггер.** Игрок находится в состоянии IDLE и не совершает ввода `hintDelaySeconds` секунд
(дефолт **5 с**, задаётся в конфиге уровня, §10.1). Таймер:

- сбрасывается на **любой** ввод, включая нелегальный свап и тап по пустой клетке — игрок,
  который что-то пробует, в подсказке не нуждается;
- **не идёт** во время RESOLVE, POST-TURN, перемешивания, WIN/LOSE-последовательностей, бонуса
  остатка ходов (§8.4), при открытом попапе и при открытой панели читов;
- не запускается, если ходов осталось 0 — уровень уже завершается.

**Что подсказывается.** Один конкретный свап: две клетки и направление. Кандидаты — все легальные
свапы по правилам VALIDATE (§5.1). Выбор детерминированный, без RNG, по первому подходящему
правилу:

| Приоритет | Кандидат | Зачем именно он |
|---|---|---|
| 1 | Свап, создающий бустер. Среди таких — дающий высший ранг по §4.2 (радужный шар → бомба → самолётик → ракета) | Подсказка не только выводит из ступора, но и обучает словарю фигур — это её главная ценность на уровнях 1–6 |
| 2 | Свап, продвигающий **первую незакрытую** цель уровня (§8.2) | Согласовано с приоритетом наведения бустеров (§6.1): игрок и автонаведение «смотрят» в одну сторону |
| 3 | Любой легальный свап | Выводит из ступора |
| 4 | Тап по бустеру | Fallback: свапов нет вовсе (бустер окружён стенами и препятствиями) |

**Свапы «бустер + бустер» из кандидатов исключены** и попадают в подсказку только при полном
отсутствии других вариантов. Комбинация — это накопленный ресурс игрока, и советовать
израсходовать его по таймеру бездействия — плохой совет: подсказка обязана разблокировать игрока,
а не играть за него.

**Тай-брейки** (обязательны, иначе подсказка невоспроизводима и её нельзя покрыть тестом):
минимальный `y`, затем минимальный `x`, затем горизонтальный свап раньше вертикального.

**Переиспользование вычислений.** Список легальных ходов уже строится на POST-TURN для проверки
перемешивания (§5.4). Он кэшируется и используется подсказкой как есть — второго прохода по полю
нет. Кэш инвалидируется при любом изменении поля.

**Взаимодействия — зафиксированные ответы:**

| Ситуация | Правило |
|---|---|
| Игрок начал ввод при показанной подсказке | Подсказка гаснет за 0.1 с, таймер сбрасывается |
| Легальных ходов нет | Подсказки нет. Перемешивание запускается на POST-TURN (§5.4), а не по таймеру подсказки — подсказка **никогда** не является триггером перемешивания |
| Игрок сделал именно подсказанный ход | Ход обрабатывается как любой другой: ни бонуса, ни штрафа |
| Подсказка показана | Ход не расходуется, цели и счётчики не затрагиваются |
| `hintDelaySeconds = 0` | Подсказка на уровне отключена |
| Игрок бездействует и дальше | Показ повторяется циклически до ввода (тайминги в §11.3) — игрок мог отвлечься от экрана, одноразовый показ он пропустит |

**Значения по уровням.** На уровнях 1–3 `hintDelaySeconds = 3` (обучение: первое знакомство с
механикой должно учить, а не проверять терпение), на остальных — 5. Это не рычаг сложности:
подсказка сокращает время на ход, но не меняет ни лимит ходов, ни winrate-цель.

## 6. Бустеры

### 6.1 Общие правила

| Ввод | Результат | Стоимость |
|---|---|---|
| Тап по бустеру | Активируется в своей клетке | 1 ход |
| Свап бустер ↔ фишка | Бустер активируется в **новой** клетке; если свап создал ещё и матч, матч разрешается в том же шаге | 1 ход |
| Свап бустер ↔ бустер | Комбинация по матрице §6.3, эпицентр — **целевая** клетка свапа (та, где лежал второй бустер) | 1 ход |
| Бустер попал в зону поражения другого бустера | Срабатывает как звено цепочки (§6.4) | 0 |

**Приоритет цели (наведение самолётика)** — единое детерминированное правило (D09):

1. Первая **незакрытая** цель в порядке, заданном в конфиге уровня.
2. Среди клеток, обслуживающих эту цель, — клетка, уничтожение которой даёт больше всего единиц
   цели (живое препятствие с 1 оставшейся жизнью приоритетнее, чем с 2).
3. Ничья → минимальный `y` (ниже полезнее для гравитации), затем минимальный `x`.
4. Незакрытых достижимых целей нет → клетка берётся из RNG-потока среди непустых клеток с
   фишками.

**Самый нужный цвет (радужный шар и комбинации с ним)** — то же правило, спроецированное на цвет:

1. Цвет первой незакрытой цели типа `CollectColor` в порядке конфига.
2. Таких целей нет → цвет, фишек которого сейчас на поле больше всего.
3. Ничья → минимальный индекс цвета.

**Зачёт целей.** Бустер, сработавший от игрока, от цепочки или в составе комбинации,
засчитывается в цель `ActivateBooster` одинаково. Комбинация двух бустеров засчитывается как
**одна активация каждого** участника. Фишки и препятствия, уничтоженные бустером, идут в свои
цели наравне с уничтоженными обычным матчем.

### 6.2 Каталог

| Бустер | Создаётся | Эффект | Тайминг |
|---|---|---|---|
| **Ракета** `rh` / `rv` | линия ровно из 4 | Уничтожает всю строку (`rh`) или весь столбец (`rv`), включая свою клетку. Проходит поле насквозь, не останавливаясь на препятствиях (D11) | луч 0.03 с/клетка; клетка гибнет в момент прохода луча |
| **Бомба** `bm` | пересечение линий, ≥5 клеток (L, T, +) | Уничтожает все клетки квадрата 5×5 с центром в своей клетке (обрезается краем поля) | 0.10 с замах, далее мгновенно; ударная волна 0.25 с |
| **Радужный шар** `rb` | линия из ≥5 | Уничтожает все фишки одного цвета. Цвет: при свапе с фишкой — цвет этой фишки, при тапе — «самый нужный цвет» (§6.1) | 0.15 с замах, луч к каждой фишке со шагом 0.04 с, фишка гибнет через 0.10 с после попадания |
| **Самолётик** `pl` | квадрат 2×2 | Летит к цели по «приоритету цели» (§6.1) и уничтожает целевую клетку + 4 ортогональных соседа | 0.10 с разгон + 0.40 с полёт по кривой + удар |

Все четыре бустера наносят препятствию 1 урон за срабатывание (D07). Неразрушимый блокер `##`
урона не получает и эффект не останавливает.

**Крайние случаи радужного шара (E06):**

| Ситуация | Поведение |
|---|---|
| Свап с обычной фишкой | Цвет = цвет этой фишки |
| Тап | Цвет = «самый нужный цвет» (§6.1) |
| Свап с другим бустером | Комбинация по §6.3 |
| На поле нет ни одной фишки (только препятствия) | Fallback: шар уничтожает свою клетку + 4 ортогональных соседа. Бустер никогда не пропадает впустую (E07) |

### 6.3 Матрица комбинаций

Эпицентр всех комбинаций — целевая клетка свапа. Комбинация стоит 1 ход. Пустых клеток в матрице
нет — это требование, а не пожелание.

| | **Ракета** | **Бомба** | **Радужный шар** | **Самолётик** |
|---|---|---|---|---|
| **Ракета** | Крест: полная строка + полный столбец через эпицентр | Толстый крест: строки `y−1…y+1` и столбцы `x−1…x+1` целиком | Все фишки самого нужного цвета превращаются в ракеты; ориентация чередуется по порядку обхода `(y ↑, x ↑)`: чётный индекс — горизонтальная, нечётный — вертикальная; выстрел со шагом 0.06 с | Стартуют 2 самолётика к целям №1 и №2; в клетке удара появляется ракета и стреляет немедленно (первая горизонтальная, вторая вертикальная) |
| **Бомба** | — | Один взрыв 7×7 с центром в эпицентре | Все фишки самого нужного цвета превращаются в бомбы и детонируют со шагом 0.08 с | Стартуют 2 самолётика к целям №1 и №2, каждый доставляет взрыв 5×5 |
| **Радужный шар** | — | — | Уничтожает **всё поле**: все фишки, каждому живому препятствию 1 урон | Шар выбирает самый нужный цвет; каждая фишка этого цвета превращается в самолётик и летит к своей цели. Кап 8 самолётиков: клетки сортируются `(y ↑, x ↑)`, первые 8 становятся самолётиками, остальные просто уничтожаются. Шаг вылета 0.08 с |
| **Самолётик** | — | — | — | Стартуют 3 самолётика к целям №1, №2, №3 по приоритету (§6.1) |

Массовые превращения обязаны срабатывать **со сдвигом по времени** (0.06–0.08 с), а не
одновременно: одновременная детонация читается как одна вспышка и обесценивает награду. Это
требование дизайна, а не полировка.

### 6.4 Цепные срабатывания

1. **Сбор, затем выстрел.** Бустер, попавший в зону поражения другого бустера, **срабатывает**, а
   не просто уничтожается (E04) — это подписной момент жанра. Стадия ACTIVATE работает волнами.
   Волна: собрать все клетки, задетые бустерами текущей волны → найти в них ещё не сработавшие
   бустеры → это следующая волна. Активировать бустер посреди обхода поля запрещено: сначала
   список, потом выстрел, иначе поле мутируется во время итерации по нему.
2. **Ритм.** Волны разделены паузой 0.12 с, иначе цепочка не читается визуально.
3. **Завершение.** Бустер помечается `consumed` при активации и больше не срабатывает в этом
   шаге разрешения (D08) — именно это не даёт двум ракетам триггерить друг друга вечно.
   Дополнительно жёсткий кап 20 волн; достижение капа логируется как ошибка (E05).
4. Бустер, сработавший от цепочки, засчитывается в цели так же, как сработавший от игрока.

## 7. Элементы поля и препятствия

### 7.1 Инфраструктура

Задание требует расширяемости. Расширяемость здесь означает, что новое препятствие — это
**данные на существующих осях**, а не новый класс с новой логикой. Оси:

| Ось | Значения | Заметки |
|---|---|---|
| `damageSource` | `AdjacentMatch` (матч в соседней ортогональной клетке или площадной урон) · `AdjacentMatchOfColor(N)` (только матч своего цвета) · `OnCell` (матч в самой клетке) · `BoosterOnly` · `None` | Первое значение — базовый ящик |
| `health` | 1 · N (с видимыми состояниями) · `Infinite` | Визуальное состояние обязано меняться на каждый снятый hp |
| `occupancy` | `OccupiesCell` (фишки в клетке нет) · `UnderChip` · `OverChip` | В скоупе используется только `OccupiesCell` |
| `gravity` | `Static` · `Falls` · `BlocksFall` · `Passable` | Ящики скоупа — `Static + BlocksFall`; `##` — `Static + Passable`: клетку занимает, падение пропускает (§5.3) |
| `spread` | `None` · `EveryNMoves` | В скоупе не используется, ось объявлена под расширение |
| `goalRole` | `Countable` · `NotCountable` | `##` — единственный `NotCountable` |
| `perTurnBehaviour` | `None` · `CycleColor` | Обновляется на POST-TURN, шаг 1 |
| `contents` | пусто · вложенный элемент (рекурсивно, глубина ≤ 3) | Задаётся отдельным списком в конфиге, не в сетке |

Реализационное следствие: препятствие — это одна сущность (`FieldElement`) с набором значений по
осям плюс визуальный профиль. Новая механика того же класса (лёд, цепь, лоза) добавляется как
новая запись данных и новый визуал, без изменений в цикле хода. Оси `spread`, `UnderChip`,
`OverChip`, `Falls` объявлены заранее именно для этого — они не используются в 12 уровнях
скоупа, но их наличие в модели определяет, придётся ли переписывать пайплайн потом.

**Общие правила урона:**

- Урон наносится на стадии DAMAGE, 1 экземпляр на источник за шаг (D07). Источник — один матч-
  компонент или одно срабатывание одного бустера.
- Урон, превышающий остаток hp, отбрасывается: перебить 2-hp ящик за один шаг на 3 урона нельзя
  «в запас».
- Препятствие считается уничтоженным и засчитывается в цель только при hp = 0 (частичный урон в
  цель не идёт).
- Клетка освобождается на стадии CLEAR того же шага; фишки могут падать через неё уже в этом шаге.

**Вложенность.** При уничтожении контейнера вложенный элемент появляется в той же клетке на
стадии CLEAR и получает **иммунитет до конца текущего шага разрешения**. Иначе одна бомба
раскрывает и уничтожает всю вложенную цепочку за один шаг, и вложенность перестаёт быть
механикой. Вложенный элемент — полноценный элемент: он засчитывается в цель своего типа и может
сам содержать вложение (глубина ≤ 3).

### 7.2 Каталог

| Токен | Название | `damageSource` | `health` | `goalRole` | Заметки |
|---|---|---|---|---|---|
| `bx` | Обычный ящик | `AdjacentMatch` | 1 | `Countable` | Базовое препятствие |
| `b2` | Ящик, 2 жизни | `AdjacentMatch` | 2 | `Countable` | Отличается от `bx` только числом жизней — проверка того, что оси работают |
| `b3` | Ящик, 3 жизни | `AdjacentMatch` | 3 | `Countable` | В 12 уровнях скоупа не используется, доступен в конфиге |
| `c1`–`c6` | Цветной ящик | `AdjacentMatchOfColor(N)` | 1 | `Countable` | Разрушается только матчем своего цвета рядом. Площадной урон от бустера — **разрушает** (бустер бесцветен) |
| `cx` | Цветной ящик, меняющий цвет | `AdjacentMatchOfColor(current)` | 1 | `Countable` | `perTurnBehaviour = CycleColor`, см. ниже |
| `##` | Неразрушимый блокер | `None` | `Infinite` | `NotCountable` | Формирует форму поля, целью быть не может |

**Правила `cx` (ящик, меняющий цвет каждый ход):**

- Начальный цвет и фаза берутся из RNG-потока при построении уровня (разные ящики
  десинхронизированы — все одновременно мигающие ящики читались бы как один объект).
- Смена цвета происходит на POST-TURN, шаг 1: `color = (color mod colorCount) + 1`. Цвет **не**
  меняется во время разрешения поля — урон считается по цвету, актуальному на стадии DAMAGE.
- Смена цвета происходит каждый ход независимо от того, получал ли ящик урон в этом ходу.
- Анимация морфа 0.25 с, играется во время POST-TURN, ввод в это время заблокирован.
- Опциональный UI: маленький пип с цветом следующего хода. Без него ящик читается как
  «случайный», с ним появляется планирование. Рекомендуется включить.

**Ответы на крайние случаи препятствий:**

| # | Вопрос | Ответ |
|---|---|---|
| E08 | Ракета останавливается на препятствии? | Нет, проходит насквозь, нанося 1 урон каждому препятствию в линии (D11) |
| E09 | Площадной урон по препятствию — 1 или по одному на клетку? | 1 на источник (D07) |
| E10 | Препятствие блокирует падение фишек? | Ящики — да (`BlocksFall`). `##` — нет: он `Passable`, фишка над ним проваливается сквозь него в свой же столбец (§5.3) |
| E11 | Два источника в одном шаге | 2 урона |
| E21 | Распространение на занятую клетку | Ось `spread` вне скоупа; правило при вводе: распространение на POST-TURN, обход `y ↓, x ↑`, клетка, созданная этим шагом, в этом же шаге не распространяется |

## 8. Цели уровня

### 8.1 Типы целей

| Тип | Параметр | Что считается | Пример записи |
|---|---|---|---|
| `CollectColor` | цвет `1…6` | Фишки этого цвета, уничтоженные **любым** способом: матчем, бустером, цепочкой | `{ CollectColor, 15, color: 1 }` |
| `DestroyElement` | токен препятствия | Препятствия этого типа, доведённые до hp = 0. Частичный урон не считается | `{ DestroyElement, 8, token: bx }` |
| `DestroyAnyColoredBox` | — | Любой цветной ящик (`c1`–`c6`, `cx`), доведённый до hp = 0 | `{ DestroyAnyColoredBox, 5 }` |
| `ActivateBooster` | тип бустера | **Срабатывания** бустера (не создания), включая цепные и в составе комбинации | `{ ActivateBooster, 3, booster: rocket }` |

`ActivateBooster` считает именно срабатывания — это выбор из двух неоднозначных вариантов, и он
зафиксирован здесь, потому что «собрать бустер» в задании допускает оба чтения. Созданный, но не
использованный бустер в цель не идёт.

### 8.2 Мультицель

- Целей на уровне 1–3. Больше трёх не читается на экране телефона.
- Для победы должны быть закрыты **все** цели.
- **Порядок целей в конфиге задаёт и порядок отображения, и приоритет наведения** самолётика и
  радужного шара (§6.1). Это делает порядок целей инструментом левел-дизайна, а не косметикой.

### 8.3 Победа и поражение

- **Победа:** все цели закрыты на POST-TURN. Каскады доигрывают полностью до проверки (E13).
- **Поражение:** ходы = 0 и хотя бы одна цель не закрыта. При одновременном выполнении обоих
  условий — победа (D14).
- **Перебор:** излишек отбрасывается, счётчик капается на таргете (E18).
- Проигранный уровень переигрывается с нуля с **новым** seed. Пройденный — открывает следующий.
- **Победа на последнем уровне набора** (сейчас 12-й): следующего уровня нет, поэтому вместо
  автозагрузки показывается экран «Контент закончился» (§11.1). Правило общее, а не привязанное к
  числу 12: последним считается уровень с максимальным `id` среди загруженных конфигов, так что
  добавление 13-го уровня ничего не ломает.

### 8.4 Бонус остатка ходов

При победе каждый оставшийся ход превращается в ракету, размещаемую на случайной клетке с фишкой
(RNG-поток попытки), и срабатывает. Шаг между ракетами 0.15 с, кап 10 конверсий. Бонусный каскад
уровень провалить не может — результат уже зафиксирован (E23). Стоит дёшево и заметно улучшает
ощущение от финала уровня.

## 9. Прогрессия и баланс

### 9.1 Кривая сложности и целевой winrate

| Уровень | Тир | Целевой winrate | Роль |
|---|---|---|---|
| 1–4 | easy | 92–96 % | Онбординг: провал здесь читается как «игра не для меня» |
| 5 | medium | 88–92 % | Первое сопротивление |
| 6 | easy | 92–95 % | Восстановление + ввод цветного ящика |
| 7 | medium | 85–90 % | Переход на 5 цветов — сильнейший рычаг сложности |
| 8–10 | easy | 90–95 % | Три ввода механик подряд, поэтому тир лёгкий |
| 11 | medium | 85–90 % | Цель на бустеры, высокая дисперсия |
| 12 | hard | 65–70 % | Витрина всего стека механик |

Гардрейлы:

- Ни один уровень не опускается ниже 12 % winrate: за этой границей игрок перестаёт объяснять
  провал своей игрой.
- Два hard-уровня подряд запрещены. После hard идёт минимум один easy.
- В продуктовой прогрессии уровень такого тира, как 12-й, стоял бы после 20-го; здесь он
  существует, чтобы продемонстрировать всю механику в тестовой сборке. Это осознанное отклонение
  от кривой, а не ошибка балансировки.

### 9.2 Ввод механик

Порядок: одна новая механика на уровень, первое знакомство — на лёгком уровне, второе появление —
в течение следующих 2–3 уровней.

| Уровень | Новая механика | Тьюториал | Повтор |
|---|---|---|---|
| 1 | базовый матч, цель на цвет, лимит ходов | да | 2 |
| 2 | две цели одновременно | да | 3 |
| 3 | обычный ящик `bx` | да | 5 |
| 4 | ящик с 2 жизнями `b2` | да | 12 |
| 5 | форма поля: стены `##` и дырки `__` | да | 7 |
| 6 | цветной ящик `c1` | да | 7 |
| 7 | 5-й цвет фишек | нет (параметр, а не механика) | 8+ |
| 8 | неразрушимый блокер как форма поля | да | 11 |
| 9 | вложенный ящик | да | — |
| 10 | ящик, меняющий цвет `cx` | да | 12 |
| 11 | цель «активировать бустеры» | да | — |
| 12 | 6-й цвет + весь стек механик | нет | — |

Бустеры не вводятся отдельными уровнями: они появляются сами из матчей и объясняются одной
подсказкой при первом создании каждого типа.

### 9.3 Вывод лимита ходов

Лимит выводится, а не назначается (D13).

**Шаг 1 — объём работы.**

```
work = max(цветовые цели: target × cost) + Σ(остальные цели: target × cost)
```

Цветовые цели идут через `max`, потому что один клир обслуживает все цветовые цели сразу: собирая
10 фишек цвета 1 за ~40 клиров, игрок попутно получает ~10 фишек цвета 2. Небоевые цели требуют
адресной игры и складываются.

**Стоимость единицы цели, `cost` (клиров на единицу):**

| Единица цели | `cost` | Источник |
|---|---|---|
| Фишка заданного цвета | `colorCount` | Расчёт: доля нужного цвета в клирах = 1/`colorCount` |
| Обычный ящик, 1 hp | 4 | Жанровая оценка |
| Ящик с N жизнями | 4 × N | Производная от строки выше |
| Цветной ящик (`c1`–`c6`) | 4 × `colorCount` / 2 | Расчёт: нужен матч конкретного цвета, но его можно целить — отсюда делитель 2 |
| Цветной сменяющийся (`cx`) | 6 | Оценка: подходит любой цвет, но нужен тайминг → 1.5 × обычного |
| Вложенный элемент (внутренний) | 5 | Оценка: базовый ящик + переоткрытие клетки |
| Активация ракеты | 14 | Оценка с надбавкой на дисперсию |
| Активация бомбы | 22 | Оценка с надбавкой на дисперсию |
| Активация самолётика | 24 | Оценка (в 12 уровнях не используется) |
| Активация радужного шара | 36 | Оценка (в 12 уровнях не используется) |

**Шаг 2 — пропускная способность хода `thr` (клеток за ход):**

| Поле | `thr` | Источник |
|---|---|---|
| Открытое 8×8 / 9×9 | 5.0 | Жанровая оценка: матч-3 даёт 3, каскады и бустеры добирают до ~5 |
| Открытое 7×7 | 4.5 | Меньше поле — короче каскады |
| Заблокировано ≤ 15 % клеток | 4.2 | |
| Заблокировано 16–30 % | 3.8 | |
| Поле разбито стенами на слабосвязные регионы | 3.4 | Стены подавляют каскады сильнее, чем их количество |

**Шаг 3 — формула:**

```
moves = ceil( work / thr × multiplier )
```

| Тир | `multiplier` |
|---|---|
| easy | 1.30 |
| medium | 1.10 |
| hard | 0.95 |
| superhard | 0.85 |

**Шаг 4 — обязательная проверка решаемости.** Каждый уровень до сдачи проходит проверку: бот или
человек проходит его при разумной игре в рамках лимита. Уровень, непроходимый при идеальной игре,
сломан независимо от того, как хорошо выглядела арифметика. Это требование дизайна, а не задача
QA «на потом».

### 9.4 Рычаги сложности, по силе убывания

1. **Число цветов** — 4 → 6 способно вдвое уронить winrate на том же поле.
2. **Лимит ходов** — линейный и предсказуемый, самый безопасный тюнинг.
3. **Плотность и кластеризация препятствий** — 8 ящиков кучей сложнее 8 ящиков вразброс, потому
   что куча гасит каскады.
4. **Форма поля** — стены и дырки, дробящие поле.
5. **Размер целей** — очевидный, но грубый: удлиняет уровень.
6. **`spawnWeights`** — тонкий и легко ломаемый рычаг; существует только как per-level данные.

Между итерациями меняется **один** рычаг, и в конфиге фиксируется какой. Уровень, отбалансированный
одновременным сдвигом трёх рычагов, не сможет перебалансировать никто, кроме автора.

## 10. Формат уровня

### 10.1 Схема конфига

Конфиг — `ScriptableObject` (`LevelConfig`) с сериализуемым текстовым `layout`. Текстовая сетка
выбрана, чтобы уровни читались и диффились в git; редактор уровней заданием не требуется.

| Поле | Тип | Заметки |
|---|---|---|
| `id` | int | Номер уровня, он же порядок прогрессии |
| `width`, `height` | int | Размер поля |
| `colorCount` | int | 4–6 |
| `moveLimit` | int | Выводится по §9.3 |
| `difficultyTier` | enum | `easy` / `medium` / `hard` / `superhard` — для аналитики |
| `goals` | list | `{ type, target, param }`; порядок = порядок отображения **и** приоритет наведения (§8.2) |
| `layout` | text grid | Сетка токенов, первая строка = `y = height − 1` (D01) |
| `contents` | list | `{ x, y, token }` — вложенные элементы, по порядку от внешнего к внутреннему |
| `spawners` | list, опц. | Индексы столбцов-спавнеров; отсутствие = дефолт (§3.3) |
| `spawnWeights` | map, опц. | Цвет → вес; отсутствие = равномерно |
| `hintDelaySeconds` | float, опц. | Задержка подсказки хода (§5.5). Отсутствие = 5; на уровнях 1–3 — 3; `0` отключает подсказку |

### 10.2 Нотация сетки

Один токен = 2 символа, токены разделены пробелом.

```
..  играемая клетка, фишка случайного цвета
t1..t6  фишка заданного цвета
__  нет клетки (дырка)
##  неразрушимый блокер
bx  обычный ящик (1 hp)        b2  ящик 2 hp        b3  ящик 3 hp
c1..c6  цветной ящик заданного цвета                cx  ящик, меняющий цвет каждый ход
rh  ракета горизонтальная      rv  ракета вертикальная
bm  бомба        rb  радужный шар        pl  самолётик
```

Вложенность в сетке **не** записывается: сетка задаёт внешний элемент, а вложения перечисляются в
`contents` по координатам. Так сетка остаётся читаемой, а глубина вложения — произвольной.

### 10.3 Полный пример уровня

Уровень 5 целиком, включая расчёт лимита ходов:

```yaml
id: 5
width: 8
height: 8
colorCount: 4
moveLimit: 26
difficultyTier: medium
goals:
  - { type: DestroyElement, target: 10, token: bx }
  - { type: CollectColor,   target: 10, color: 2 }
layout: |
  __ .. .. .. .. .. .. __
  .. .. .. .. .. .. .. ..
  .. .. ## .. .. ## .. ..
  .. bx ## .. .. ## bx ..
  .. bx ## bx bx ## bx ..
  .. bx ## bx bx ## bx ..
  .. .. ## .. .. ## .. ..
  .. .. .. .. .. .. .. ..
contents: []
spawners: [1, 2, 3, 4, 5, 6]   # = дефолт, выписан явно для наглядности
```

Расчёт: `work = 10 × 4 (ящики) + 10 × 4 (цвет, max по цветовым целям) = 80`; поле разбито стенами
на регионы → `thr = 3.4`; тир medium → `multiplier = 1.10`.
`moves = ceil(80 / 3.4 × 1.10) = ceil(25.9) = 26`.

Проверка потока (§3.4, правило 1):

- Столбцы 0 и 7 спавнерами не являются — в верхней строке у них дырка. Клетки `(0, 6)` и `(7, 6)`
  пополняются диагональным скольжением из `(1, 7)` и `(6, 7)`.
- Столбцы 2 и 5 перекрыты стенами на `y = 1…5`, но ширина стены — 1 клетка, поэтому `(2, 0)` и
  `(5, 0)` пополняются по диагонали из `(1, 1)` / `(3, 1)` и `(4, 1)` / `(6, 1)`.
- Клетки `(2, 6…7)` и `(5, 6…7)` — альковы над стеной: спавнер их наполняет, фишки уходят из них
  диагонально в соседние столбцы или матчами по горизонтали.
- Мёртвых карманов нет.

**Правило ширины стены (следствие §5.3, обязательно при авторинге уровней).** Клетка под
вертикальным блоком стен шириной `W` пополняется по диагонали только с внешних сторон блока.
При `W ≥ 3` центральные клетки под блоком не пополняются никогда — это мёртвый карман, и
валидация §3.4 такой уровень отклонит. Поэтому **сплошной блок стен не шире 2 клеток**; более
широкие преграды собираются из блоков шириной ≤ 2, разнесённых по вертикали (см. уровень 8).

## 11. UI и обратная связь

### 11.1 Экраны

| Экран | Содержимое |
|---|---|
| Boot / Loading | Прогресс загрузки, логотип |
| Level | Поле, HUD, кнопка читов |
| Win popup | «Level complete», прогресс целей, кнопка «Next» |
| Lose popup | «Out of moves», прогресс целей, кнопка «Retry» |
| Cheat panel | Оверлей, §12 |
| End of content | «All levels complete», номер последнего уровня, кнопка «Play again from level 1». Панель читов остаётся доступной — переход на произвольный уровень с этого экрана работает |

**Язык интерфейса — английский.** Сборка одноязычная, слоя локализации нет: подписи здесь и в §12
приведены ровно так, как выводятся на экран.

Меню уровней нет: после победы автоматически загружается следующий уровень, после поражения —
текущий. Исключение — победа на последнем уровне набора: вместо автозагрузки открывается экран
End of content (§8.3).

**Заглушка, а не фича.** Экран существует, чтобы поведение после последнего уровня было
определённым, а не вылетом в никуда. В продуктовой версии его место занимает мета-слой (§16):
именно туда игрок должен возвращаться между уровнями, и именно он даёт цель верхнего уровня,
которой у сборки сейчас нет.

### 11.2 HUD

- Счётчик ходов — крупно, слева сверху. Уменьшается на COMMIT (D04). При значении ≤ 5 —
  пульсация 0.6 с/цикл.
- Панель целей — иконка + `текущее/таргет` на каждую цель, в порядке из конфига (§8.2).
  Закрытая цель получает галочку и перестаёт пульсировать.
- Кнопки «Restart» и «Cheats» — справа сверху.

### 11.3 Тайминги (контракт для реализации)

Заданию нужны «простые эффекты», но «приятное схлопывание» — не правило, которое можно
запрограммировать. Ниже — правила.

| Момент | Тайминг |
|---|---|
| Свап | 0.15 с, ease-out |
| Нелегальный свап | 0.10 с туда + 0.10 с обратно |
| Уничтожение фишки при матче | scale 1 → 1.15 за 0.06 с, затем scale → 0 и alpha → 0 за 0.14 с. Итого **0.20 с** |
| Начало опадания | Строго **после** завершения всех FX уничтожения текущего шага (стадия ANIMATE перед GRAVITY) |
| Падение | ускорение 40 клеток/с², максимум 18 клеток/с; посадка — squash 0.06 с; задержка между соседними фишками 0.03 с |
| Появление из-за края поля | Фишка стартует на 1 клетку выше верхней строки, вне маски поля, и падает по тем же правилам |
| Пауза между шагами каскада | 0.08 с после стабилизации перед следующим DETECT |
| Ракета | 0.03 с/клетка, шлейф, тряска камеры 0.05 с амплитудой 4 px |
| Бомба | 0.10 с замах (scale 1 → 1.2), вспышка, ударная волна 0.25 с, тряска 0.12 с амплитудой 10 px |
| Радужный шар | 0.15 с замах, лучи со шагом 0.04 с, фишка гибнет через 0.10 с после попадания луча |
| Самолётик | 0.10 с разгон + 0.40 с полёт по кривой Безье + удар |
| Волна цепочки | 0.12 с между волнами (§6.4) |
| Массовое превращение (комбо с радужным шаром) | 0.06–0.08 с между срабатываниями |
| Тик счётчика цели | 0.15 с на единицу, суммарно не дольше 1.0 с (при большом приросте шаг сжимается) |
| Морф цвета у `cx` | 0.25 с на POST-TURN |
| Перемешивание | 0.35 с разлёт + 0.35 с сбор |
| Бонус остатка ходов | 0.15 с между ракетами, кап 10 |
| Подсказка хода: появление | Пульсация двух клеток свапа, scale 1 → 1.08, 0.5 с на цикл, 3 цикла; между ними — стрелка направления свапа, alpha 0 → 1 за 0.2 с |
| Подсказка хода: повтор | Пауза 2.0 с после трёх циклов, затем показ повторяется — циклически, до ввода (§5.5) |
| Подсказка хода: скрытие | 0.1 с на любой ввод |

Ключевое правило из задания, вынесенное отдельно: **опадание не начинается, пока не завершились
эффекты уничтожения** — это стадии 7 и 8 пайплайна §5.1, а не пожелание к аниматору.

## 12. Читы и инструменты

Панель читов открывается экранной кнопкой (иконка жука, справа сверху). Только экранные элементы,
горячих клавиш нет — по требованию задания.

| Элемент | Действие |
|---|---|
| Поле ввода номера уровня + «Go» | Загружает указанный уровень с нуля. Некорректный номер — кнопка неактивна |
| «Win level» | Закрывает все цели, запускает WIN-последовательность (включая бонус остатка ходов) |
| «Lose level» | Обнуляет ходы, запускает LOSE-последовательность |
| «+5 moves» | Добавляет 5 к счётчику |
| Выбор бустера (4 кнопки) + тап по клетке | Ставит выбранный бустер в клетку, ход не расходуется |
| Seed: поле + «Apply» / «Restart» | Показывает seed текущей попытки, позволяет ввести свой и перезапустить уровень воспроизводимо (D12) |
| «Free moves» (тумблер) | Ходы не списываются — для отсмотра механик |
| «Show coordinate grid» (тумблер) | Оверлей с `(x, y)` в каждой клетке — для сверки с конфигом |
| «Hint now» | Показывает подсказку хода немедленно, не дожидаясь таймера (§5.5) |
| «Disable hints» (тумблер) | Глушит таймер простоя — для отсмотра поля без мигающих клеток |

**Исключение из релиза.** Панель собирается под `#if MATCH3_CHEATS`; дефайн включён в
Development-билдах и в редакторе, в релизной конфигурации WebGL — выключен. Префаб панели
подгружается только при активном дефайне, чтобы не попасть в релизный билд ассетами.

## 13. Технические требования

| Параметр | Значение |
|---|---|
| Платформа | Unity WebGL (Unity 6000.3.21f1), URP, uGUI |
| Целевой FPS | 60 на десктопном Chrome/Edge; допустимый минимум 30 |
| Референсное разрешение | 1080 × 1920, Canvas Scaler — Scale With Screen Size, match 0.5 |
| Кадр на странице | **Леттербокс 9:16:** канвас вписывается в окно браузера с сохранением соотношения, поля по бокам заливаются цветом стены. Минимальная ширина канваса — 420 CSS px (клетка 9×9 = 44 px, нижняя граница тач-таргета) |
| Разрешение рендера | Drawing buffer = CSS-размер × `min(devicePixelRatio, 2)`, **потолок 1080 × 1920**. Выше потолка UI и спрайты уходят в апскейл, а стоимость пикселей растёт квадратично |
| Диапазон соотношений | 9:16 … 16:9 — требование к **движку**: поле центрируется в квадратной области, HUD перекомпонуется над/под полем. Страница при этом фиксирует 9:16 (строка выше), поэтому в шипнутой сборке диапазон отрабатывает только при принудительном изменении формы канваса |
| Размер клетки | `min(area / width, area / height)`, где `area` — сторона квадратной области поля |
| Сохранение | `PlayerPrefs` (в WebGL — IndexedDB), ключи `progress.currentLevel` и `progress.allCompleted` (bool). Пишется при победе и при поражении |
| Прогресс после последнего уровня | `currentLevel` остаётся равным `id` последнего уровня, `allCompleted = true`. Вход в игру с этим флагом открывает экран End of content, а не уровень. Кнопка «Play again from level 1» ставит `currentLevel = 1`, `allCompleted = false` |
| Сохранение состояния поля посреди хода | Не поддерживается: при перезагрузке страницы уровень начинается заново с новым seed (E24). Осознанное упрощение для тестовой сборки |
| RNG | Один поток `System.Random` на попытку уровня; seed случайный, логируется и виден в читах. Потребители в фиксированном порядке: генерация начального поля → цвета из спавнеров → фаза `cx` → тай-брейки наведения → перемешивание → бонус остатка ходов (D12) |
| Детерминизм | Одинаковые seed + одинаковая последовательность ввода дают одинаковую партию |
| Пулинг | Фишки, препятствия и FX — через пул; на WebGL аллокации в каскаде дают заметные фризы |

**Генерация начального поля (E20).** Клетки заполняются в порядке `y ↑, x ↑`; если поставленный
цвет замыкает линию из 3, цвет перевыбирается (до `colorCount − 1` попыток на клетку, затем
берётся любой не образующий линию). Затем проверяется наличие хотя бы одного легального хода; при
неудаче поле генерируется заново, до 50 попыток, затем — ремонтный проход, меняющий местами две
фишки до появления легального хода.

## 14. Метрики

Событий немного, но без них баланс — угадывание. Для тестовой сборки достаточно вывода в консоль
и в лог-файл, схема совпадает с продуктовой.

| Событие | Поля |
|---|---|
| `level_start` | `id`, `tier`, `attempt`, `seed` |
| `level_end` | `id`, `result` (`win` / `lose` / `deadlock`), `movesUsed`, `movesLeft`, прогресс по каждой цели, `seed` |
| `booster_fired` | `type`, `source` (`player` / `chain` / `combo`), `comboWith` |
| `shuffle_triggered` | `id`, `movesUsed`, номер попытки перемешивания |
| `cascade_depth` | `id`, максимальная глубина за ход |
| `wave_cap_hit` | `id` — всегда баг, не баланс |
| `hint_shown` | `id`, `movesLeft`, приоритет сработавшего правила выбора (1–4, §5.5) |
| `hint_followed` | `id`, совпал ли следующий ход игрока с подсказанным свапом |

| Метрика | Порог действия |
|---|---|
| Winrate уровня | Выход из целевой полосы (§9.1) более чем на 10 п.п. → перебалансировать |
| Попыток до первого прохождения | > 4 в среднем на не-hard уровне → перебалансировать |
| Остаток ходов при победе | Стабильно > 6 → лимит слишком щедрый |
| Распределение причин поражения | Любой `deadlock` → баг |
| Частота срабатывания бустеров | Близко к нулю на уровне → условия создания слишком редкие |
| Средняя глубина каскада | Целевой диапазон 1.3–1.8; падение ниже → поле слишком раздроблено |
| Доля ходов, сделанных после подсказки | > 30 % на уровне → поле нечитаемо (визуальный перегруз или неудачная палитра), а не «сложно». Правится артом и формой поля, не лимитом ходов |

## 16. Вне скоупа

- **Монетизация** — жизни, валюта, инвентарь бустеров, офферы продолжения, цены. Задание её не
  требует; экономика не проектировалась.
- **Мета-слой** — прогресс вне уровней, декор, карта, коллекции. Следствие: у игры нет цели
  верхнего уровня, кроме «пройти 12 уровней»; после последнего стоит заглушка (§11.1), а не
  контент.
- **Предматчевые бустеры** (E22) — нет инвентаря, значит нет и ввода бустера до первого хода.
- **Собираемые падающие элементы** (`collectible`) и цель «спустить N штук» (E12) — в задании нет.
- **Распространяющиеся препятствия** (лоза), препятствия `UnderChip` / `OverChip` (лёд, цепь),
  падающие препятствия — оси под них объявлены в §7.1, конкретные препятствия не спроектированы.
- **Редактор уровней** — задание явно не требует; уровни авторятся текстовой сеткой (§10.2).
- **Горячие клавиши читов** — задание явно требует только экранные элементы.
- **Звук** — не проектировался; тайминги §11.3 задают точки, к которым его можно привязать.
- **Локализация, аналитика на сервер, лидерборды, мультиплеер.**
